## Learnings

- Discord guild-message search is async: first call returns `202 Accepted` with no `messages` key; poll the identical request until `200` (ready in ~2s). Mocked tests missed this because respx fixtures returned `200` immediately — a Phase-Gate lesson: the live probe exists precisely to falsify mocked assumptions.
- Plain DM channels (`type: 1`) have no `name` field — identity lives in `recipients[].username/global_name`; group DMs (`type: 3`) carry `name`. A DM-listing surface must derive labels from recipients, not `name`.
- `patch()` auto-detects async functions and produces AsyncMock — a sync call site returns a coroutine silently; `asyncio.run(capture())` is the correct CLI pattern for the async browser capture.
- Discord user search (`/guilds/{id}/messages/search`) returns nested arrays (match + context neighbors) — client flattens before the tool boundary; mock fixtures must use the real envelope shape (`{"total_results", "messages": [[...]]}`) once tests run through the real client.
- Unreachable-line bug found by the audit: `raise_for_status()` before the exhaustion `RuntimeError` fired `HTTPStatusError` first — the declared error type was unraisable. Gap tests are how dead declared behavior is caught.
- The ported Ichnos OTP regex missed attached-colon keyword form (`password: 95172243`); fixed with `\s*` separators. Port ≠ verbatim-safe: boundary modules must be re-tested against the new host's surface.
- Windows DPAPI roundtrip is testable in-process via `win32crypt` without elevation; `DISCORD_MCP_DIR` env override makes the credential path testable.
- Git on a fresh repo: `git reset --soft HEAD~1` fails on a root commit — use `git update-ref -d refs/heads/master` + `git reset` to unstage and re-split commits before first push.
- Mocking internal boundaries hides shape errors (the search envelope bug surfaced only when tests were reworked to respx) — the banned pattern is load-bearing, not aesthetic.
